# פריסה ל-Vercel

המדריך הזה מעלה את INFINIX Simulator ל-Vercel יחד עם **מאגר שאלות משותף**:
מנהל מעלה קובץ JSON פעם אחת, וכל התלמידים רואים אותו — בלי לגעת בקוד ובלי
לפרוס מחדש.

---

## מה משתנה לעומת GitHub Pages

| | GitHub Pages | Vercel |
|---|---|---|
| האתר עצמו | סטטי | סטטי (זהה) |
| מאגר שאלות | נצרב ב-build, או מיובא ל-localStorage של כל דפדפן בנפרד | מאגר אחד ב-Vercel Blob, נקרא על ידי כולם |
| העלאת מאגר | לערוך את הרפו ולפרוס מחדש | להעלות JSON ממסך הניהול |

הבנייה ל-GitHub Pages ממשיכה לעבוד כרגיל. בלי Blob store מוגדר, המערכת
נופלת חזרה בדיוק להתנהגות הישנה.

---

## שלב 1 — העלאה ל-Git

```bash
git add -A
git commit -m "feat: editorial redesign + shared question bank on Vercel"
git push
```

## שלב 2 — חיבור הפרויקט ל-Vercel

1. ב-[vercel.com/new](https://vercel.com/new) — Import את הרפו.
2. Vercel יקרא את `vercel.json` ויגדיר לבד:
   - Build Command: `pnpm build:pages`
   - Output Directory: `dist/public`
   - הפונקציה `api/question-bank.ts`
3. **אל תלחץ Deploy עדיין** — קודם משתני הסביבה (שלב 3).

## שלב 3 — משתני סביבה

Project → Settings → Environment Variables. הגדר לשלוש הסביבות
(Production, Preview, Development):

| שם | ערך | למה |
|---|---|---|
| `VITE_ADMIN_EMAIL` | המייל של המנהל | חשבון המנהל |
| `VITE_ADMIN_PASSWORD` | סיסמה זמנית חזקה | מוחלפת בכפייה בכניסה הראשונה בכל דפדפן |
| `VITE_STUDENT_EMAIL` | למשל `student@infinix.org.il` | כניסת תלמידים. השאר ריק כדי לבטל |
| `VITE_STUDENT_PASSWORD` | סיסמה משותפת לתלמידים | לא נדרשת החלפה |
| `ADMIN_UPLOAD_TOKEN` | `openssl rand -base64 32` | מרשה פרסום מאגר |

**אל תגדיר** `VITE_BASE_PATH` — הוא נועד לתת-נתיב של GitHub Pages ויישבור
את הנכסים על דומיין שורש.

> `VITE_ADMIN_PASSWORD` נצרב ל-JS bundle, כמו כל משתנה `VITE_`. זה מקובל
> רק משום שהיא חייבת להתחלף בכניסה הראשונה. `ADMIN_UPLOAD_TOKEN` לעומתה
> **לעולם לא מגיע לדפדפן** — הוא נבדק בפונקציית השרת.

## שלב 4 — Blob store

Project → Storage → Create → **Blob**.

Vercel מזריק את `BLOB_READ_WRITE_TOKEN` לפרויקט אוטומטית. אין מה להעתיק.

עכשיו Deploy.

## שלב 5 — פרסום המאגר הראשון

1. היכנס לאתר עם חשבון המנהל (תידרש להחליף סיסמה).
2. **ניהול → תוכן → פרסום לכל התלמידים**.
3. הדבק את `ADMIN_UPLOAD_TOKEN` בשדה "טוקן ניהול" ולחץ **שמור**
   (נשמר בדפדפן שלך בלבד, כדי לא להקליד בכל פעם).
4. **פרסם קובץ JSON** ובחר את `question_bank_infinitycloser.json`.

התלמידים יראו את המאגר החדש תוך עד דקה (ה-CDN מחזיק את התשובה 30 שניות).

## איך המאגר נבחר

בכל טעינה האפליקציה יורדת ברשימה עד למקור הראשון שקיים:

1. **מאגר מקומי** — קובץ שיובא לדפדפן הזה דרך "העלה" במסך הבית.
   גובר מכוונה: מי שייבא אותו עשה זאת במפורש. מוצג בבירור כ"מקומי",
   ויש כפתור להסרה.
2. **מאגר משותף** — מה שפורסם דרך מסך הניהול. זה מה שרוב המשתמשים רואים.
3. **מאגר מובנה** — `client/public/question_bank_infinitycloser.json`,
   נבנה יחד עם האתר.
4. **תוכן הדגמה** — אם אין אף מאגר עם שאלות שמישות.

מסך הבית ומסך הניהול מציגים תמיד איזה מקור פעיל. אם קיים מאגר מקומי
שמסתיר מאגר משותף, מסך הניהול מתריע — זה המצב היחיד שבו המנהל והתלמידים
רואים שאלות שונות.

## פיתוח מקומי

`vite.config.ts` מגיש את אותו `/api/question-bank` עם אותם שלושה verbs,
מול קובץ בדיסק — כך שאפשר לתרגל את זרימת הפרסום בלי לפרוס:

```bash
cp .env.example .env.local   # מלא ADMIN_UPLOAD_TOKEN בערך כלשהו
pnpm dev
```

מה שמתפרסם מקומית נשמר ב-`.local-question-bank.json` (git-ignored).
מחיקת הקובץ שקולה ל"בטל פרסום".

בדיקה מהירה מהטרמינל:

```bash
curl -X PUT http://localhost:3000/api/question-bank -H "Authorization: Bearer $ADMIN_UPLOAD_TOKEN" -H "Content-Type: application/json" --data-binary @question_bank_infinitycloser.json
```

## חשבונות — איך זה עובד בפועל

אין שרת אימות. חשבונות נשמרים ב-`localStorage` של כל דפדפן בנפרד, ולכן:

- **החשבון נוצר בכניסה, לא בטעינת הדף.** מי שלא הקליד את סיסמת המנהל
  לא מקבל חשבון מנהל. (בגרסה קודמת כל מי שפתח את האתר קיבל אחד.)
- **חשבון שמור תמיד גובר על משתנה הסביבה.** אחרי שהחלפת סיסמה, שינוי
  `VITE_ADMIN_PASSWORD` ב-Vercel לא ידרוס אותה.
- **שינוי הסיסמה ב-Vercel משפיע רק על דפדפנים שעוד לא נכנסו.** זו
  ההתנהגות הנכונה, אבל היא אומרת שדפדפן שנתקע עם ערך ישן צריך ניקוי.
- **מנהל לא יכול להקצות חשבונות לתלמידים מרחוק.** משתמש שנוצר במסך
  הניהול קיים רק בדפדפן של אותו מנהל. לכן קיימת כניסת התלמידים המשותפת.

### נעילה מחוץ למערכת

אם החלפת סיסמה ושכחת אותה, או שדפדפן תקוע על ערך ישן — נקה את החשבון
בקונסול של הדפדפן ותיכנס מחדש עם הערך שב-Vercel:

```js
localStorage.removeItem('ic_auth_users_v2');
localStorage.removeItem('ic_active_session_v1');
location.reload();
```

היסטוריית האימונים לא נמחקת.

## מה זה עדיין לא

הכניסה למערכת נשארה **שער תצוגה**, לא אבטחה — היא רצה בדפדפן של המשתמש
וניתנת לעקיפה. ראה [SECURITY.md](SECURITY.md). מה שהשתנה: פעולת הכתיבה
היחידה שמשפיעה על כולם — פרסום מאגר — מוגנת בטוקן שנבדק בשרת, ולכן היא
כן אמיתית.

חשבונות משתמשים, היסטוריית אימונים וציונים עדיין נשמרים בדפדפן של כל
משתמש בנפרד. כדי לרכז אותם צריך אימות אמיתי ומסד נתונים — פרויקט נפרד.
